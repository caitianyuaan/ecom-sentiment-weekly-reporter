# 飞书原生卡片格式

飞书消息卡片不是浏览器，不得把 HTML/CSS 页面或完整 Markdown 报告直接塞入一个富文本组件后称为“HTML 卡片”。

## 双产物原则

- **完整报告**：继续生成 `consulting_compact` HTML，保留完整新闻内容和浏览器布局。
- **群内消息**：生成 Card JSON 2.0，使用 `msg_type: interactive` 发送。
- 卡片中的“查看完整 HTML 报告”按钮指向可访问的完整报告；本地 `file://` 地址不能发给群成员。

## 卡片结构

默认生成：

1. 一张跨市场概览卡：标题、周期、最多 3 条重点、各市场一句摘要、完整报告按钮。
2. 每个市场一张明细卡：按原报告顺序列出新闻条目。
3. 每条新闻是独立 Markdown 组件，条目之间使用分隔线；不得把整份市场报告拼成一个巨型 Markdown 字符串。
4. 明细条目依次显示平台/类型/情绪、标题、重点、摘要、UXR、日期和来源。
5. 署名只在市场明细卡末尾出现一次。

如果单市场条目超过飞书卡片限制，在新闻条目边界拆成多张连续编号卡片；不得截断摘要，也不得降级为一张 Markdown/Post 长消息。

## 禁止项

- 不使用“HTMLBox”作为默认或假定能力。
- 不在标题上标注“HTML/Rich Card”，除非实际载荷是 Card JSON 2.0 interactive 消息。
- 不把 Markdown/Post 套一层卡片外壳冒充 HTML。
- 不使用双栏市场正文；窄屏下可读性优先。

使用 `scripts/render_feishu_cards.py` 从结构化报告 JSON 生成卡片 JSON。发送前检查 `schema` 为 `2.0`、`msg_type` 为 `interactive`，且每条新闻对应独立组件。
